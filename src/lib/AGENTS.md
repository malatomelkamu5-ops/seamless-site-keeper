# src/lib notes

- Mathematics teachers may also upload and view SAT papers (`uploadSubjects`); a paper's `target_stream` comes from the teacher, so a Social Science teacher's SAT reaches only Social Science students.
- One active paper per stream: `exam_settings.active_bank_id` (Natural) and `social_bank_id` (Social) can be live together; every exam call resolves the student's paper by stream.
- Student devices persist answers immediately to localStorage, debounce answer saves (`ANSWER_SYNC_DEBOUNCE_MS`), coalesce in-flight syncs, and send jittered `HEARTBEAT_MS` (15s) keep-alives; brief network dips show a non-blocking banner while sustained Director-exam offline loss (`OFFLINE_FREEZE_DELAY_MS` / `DISCONNECT_GRACE_SEC` = 45s) freezes the timer safely at `last_seen_at`. `usePublicState` pauses during active exams, `getPublicState` throttles maintenance RPCs, and `student()` updates `session_seen_at` at most once per `SESSION_TOUCH_MS`.
- Teacher paper import: the browser turns PDFs/photos into page pictures (pdfjs) and .docx into text + embedded pictures (mammoth), `teacherScanPaper` reads them via `src/lib/paper.server.ts`; formulas come back as `$…$` LaTeX (KaTeX + mhchem via `MathText`), shared passages as `passage`, and figures are cut client-side from the model's page boxes and stored in the private `question-figures` bucket (paths in `figure`, streamed directly as data URLs after verifying access). `normalizeScanned` keeps an answer only with proof on the paper.
- The exam screen never uses native prompt/confirm/alert (they drop browsers out of fullscreen); it uses in-page dialogs and the cross-browser helpers in `src/lib/fullscreen.ts`, re-entering fullscreen on any tap until the exam ends.
- Exam Help requests are `exam_events` rows of kind `help` (one per student per `HELP_COOLDOWN_SEC`), pinned to the top of the Director's alerts.
- With `auto_close` on, `directorUpdate`/`directorClock` refuse a manual close of a live session; the Director only opens it.
- Telegram bot: Telegram calls `/api/public/telegram/webhook` (secret header derived from the connection key); conversation state lives in `telegram_users`, logs/help requests in `telegram_messages` (update_id makes deliveries idempotent, passcodes are never logged), all server-only via the gateway in `telegram.server.ts`. Status notices are claimed by compare-and-set on `telegram_settings.last_*` so each change is announced once, from any caller. Chats link to a student (`id_confirmed = true`) and read profile/results only after proving Student ID + result passcode.
- Face checks (uncovered face, duplicate face) run at registration through the AI gateway SDK in `src/lib/face.server.ts`; every registered face has a small stored tile (`thumbs/<photo_path>`, made by `src/lib/face-grid.ts`, rebuilt from the full photo if missing) and all tiles go into one numbered school-wide grid screened by a single light request, because per-batch photo requests exhausted AI credit; a grid match only blocks after two one-to-one confirmations (both orders) against that student's full photo agree, since look-alike classmates and siblings get named by the grid. Pass/fail rules live in pure helpers (`uncoveredVerdict`, `screenMatch`, `isSamePerson`) covered by `face-check.test.ts` and `face-grid.test.ts`.
- Re-admitting a blocked attempt restores the time left at blocking (`readmitDeadline`), clears warnings, score and that subject's round result, and parks it as `pause_reason='readmit'`; `studentExam` restarts the clock when the student's screen reopens, so they aren't cut off or marked disconnected while walking back.
- A paper's "Given" sheet (values, constants, formula sheets, data tables) is one `question_banks.given` text per bank, read by the paper scanner (`readGiven`) and drawn by `GivenSheet` (rows with ` | ` become tables via `givenBlocks`); students open it from the exam header at any time. "Remove all" empties a bank as a draft; `bankSaveProblem` refuses an empty paper that is live or being submitted.
- Practice mode (`exam_settings.practice_mode`, `exam_attempts.practice`): practice attempts never write round_results or alerts, never block, return an instant review from studentSync and are then deleted so students can retry; toggling the mode deletes leftover practice attempts.
- Class quizzes (`class_quizzes`, `quiz_attempts`, `src/lib/quiz.functions.ts`, rules in `quiz-rules.ts`) are teacher-run and never touch Director exams, round_results or alerts: questions are copied from the teacher bank at start, only the chosen `sections` of the teacher stream can open it, the student Exam screen is reused with `quizId` (2 warnings, block on the 3rd, teacher re-admit via `readmitDeadline`), and answers/score show only after `results_released`.
- Android exam app: `android-app/` (plain WebView, no Gradle; `build.sh` writes `public/BHSSS-Exam.apk`, currently v1.3) sets FLAG_SECURE and exposes `window.BHExamApp.lock/unlock/openUrl` plus `DownloadListener` for `.apk` links; rebuilds must reuse the same signing keystore (kept in private Files metadata) or updates will not install over the old app. `AppUpdateGate` in `__root.tsx` blocks older `BHSSSExamApp` versions below `CURRENT_APP_VERSION` across the whole app until updated.
- Exam client gates (`src/lib/telegram-webview.ts`): exams and class quizzes are refused before `<Exam>` mounts inside Telegram's mini-app viewer (`TelegramBlock`) and on mobile/tablet web browsers outside the installed app (`AppRequiredBlock`, also catching phone "Desktop site" mode), while laptops/PCs remain allowed on the web with fullscreen, blackout-on-blur, and student watermark protections.
